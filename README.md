# Facial Emotion Recognition Module

Система розпізнавання емоцій у реальному часі за зображенням із вебкамери. Проєкт використовує MediaPipe Face Landmarker для пошуку точок обличчя, OpenCV для роботи з камерою та відображення результату, PostgreSQL для зберігання користувачів, а також rule-based класифікатор емоцій.

Застосунок має повноцінний графічний інтерфейс із двома сценаріями: швидкий пробний запуск без збереження даних і авторизований режим зі збереженням профілю обличчя користувача в PostgreSQL.

Користувацький інтерфейс застосунку відображається англійською мовою.

## Можливості

- запуск застосунку через графічний інтерфейс;
- режим `Try` без реєстрації та без збереження даних користувача;
- реєстрація та вхід користувача;
- зберігання користувачів у PostgreSQL;
- безпечне зберігання паролів у вигляді PBKDF2-хеша;
- збереження координат обличчя для конкретного користувача;
- повторне використання збережених координат під час наступного входу;
- кнопка `Recapture Face` для оновлення координат обличчя;
- вихід з акаунта та повне закриття системи;
- розпізнавання емоцій в окремому вікні камери;
- блокування класифікації, якщо обличчя сильно повернуте або нахилене;
- експорт результатів авторизованих сесій у `output/`.

## Розпізнавані емоції

Система класифікує вираз обличчя в одну з категорій:

- `Happy`
- `Fear`
- `Surprised`
- `Angry`
- `Sad`
- `Disgusted`
- `Contempt`
- `Neutral`

У вікні камери результат показується англійською мовою, наприклад:

```text
Emotion: Happy
```

Якщо обличчя повернуте або нахилене занадто сильно, система не класифікує емоцію і показує:

```text
Emotion: Unclassified
Face: turn forward
```

Стан `Unclassified` не є емоцією. Він означає, що поточне положення обличчя недостатньо фронтальне для надійної класифікації.

## Параметри міміки

Класифікатор використовує такі числові параметри, розраховані з точок MediaPipe:

| Параметр | Значення |
|---|---|
| `ear_avg` | Середня відкритість очей. Більше значення означає ширше відкриті очі. |
| `mar` | Відкритість рота. Більше значення означає сильніше відкритий рот. |
| `smile_coeff` | Коефіцієнт усмішки. Додатні значення відповідають усмішці, від'ємні - опущеним куточкам рота. |
| `mouth_width` | Ширина рота. Більше значення часто підсилює ознаку усмішки. |
| `brow_dist` | Відстань між бровами. Менше значення означає зведені/насуплені брови. |
| `mouth_asymmetry` | Асиметрія рота. Більше значення означає помітніше викривлення одного кута рота. |
| `upper_lip_raise` | Підняття верхньої губи. Більше значення означає сильніше підняття верхньої губи. |
| `face_yaw_ratio` | Горизонтальний поворот обличчя відносно центра. Велике абсолютне значення означає поворот ліворуч або праворуч. |
| `face_roll_degrees` | Нахил обличчя в градусах, розрахований за лінією очей. |

Після калібрування система працює в режимі `CALIBRATED` і порівнює поточну міміку з індивідуальним нейтральним baseline. У формулах нижче `d_` означає різницю між поточним значенням і baseline, наприклад `d_ear = ear_avg - baseline["ear_avg"]`.

Якщо baseline відсутній, система працює в режимі `ABSOLUTE` і використовує абсолютні пороги.

## Правила класифікації емоцій

Правила перевіряються послідовно в такому порядку: `Surprised`, `Fear`, `Happy`, `Contempt`, `Disgusted`, `Angry`, `Sad`, потім `Neutral`. Якщо міміка підходить під кілька наборів умов, буде вибрана перша емоція з цього порядку.

Перед застосуванням правил система перевіряє положення обличчя. Якщо `abs(face_yaw_ratio) > 0.18` або `abs(face_roll_degrees) > 15`, емоція не класифікується і повертається `Unclassified`.

### `Surprised`

Міміка: широко відкриті очі та сильно відкритий рот.

Абсолютний режим:

- `ear_avg > 0.30`
- `mar > 0.50`

Калібрований режим:

- `d_ear > 0.04`
- `d_mar > 0.35`

### `Fear`

Міміка: очі відкриті ширше звичайного, рот помірно або сильно відкритий, без усмішки та без помітної асиметрії.

Абсолютний режим:

- `ear_avg > 0.30`
- `0.15 < mar <= 0.50`
- `smile_coeff < 0.005`
- `mouth_asymmetry < 0.013`

Калібрований режим:

- `d_ear > 0.04`
- `0.08 < d_mar <= 0.35`
- `d_smile < 0.006`
- `d_asym < 0.008`

### `Happy`

Міміка: усмішка, рот трохи відкритий або розтягнутий у ширину.

Абсолютний режим:

- `smile_coeff > 0.005`
- додатково виконується хоча б одна умова:
  - `mar >= 0.10`
  - `mouth_width > 0.43`

Калібрований режим:

- `d_smile > 0.006`
- додатково виконується хоча б одна умова:
  - `d_mar > -0.01`
  - `d_mouth_width > 0.015`

### `Contempt`

Міміка: асиметричний вираз рота, один кут рота вираженіший, рот не відкритий широко, верхня губа піднята.

Абсолютний режим:

- `mouth_asymmetry > 0.013`
- `mar < 0.15`
- `smile_coeff > -0.002`
- `upper_lip_raise >= 0.040`

Калібрований режим:

- `d_asym > 0.008`
- `d_mar < 0.08`
- `d_smile > -0.003`
- `d_lip_raise > -0.015`

### `Disgusted`

Міміка: очі звужені, брови зведені, рот помірно відкритий, без явної усмішки.

Абсолютний режим:

- `ear_avg < 0.26`
- `brow_dist < 0.118`
- `0.10 < mar < 0.50`
- `smile_coeff < 0.005`

Калібрований режим:

- `d_ear < -0.03`
- `d_brow < -0.012`
- `0.08 < d_mar < 0.35`
- `d_smile < 0.006`

### `Angry`

Міміка: зведені брови, очі не надто широко відкриті й не надто примружені, рот майже закритий, немає усмішки або сильної асиметрії, верхня губа достатньо піднята.

Абсолютний режим:

- `smile_coeff < 0.005`
- `mouth_asymmetry < 0.013`
- `upper_lip_raise >= 0.050`
- `mar < 0.08`
- `brow_dist < 0.118`
- `0.26 <= ear_avg <= 0.30`

Калібрований режим:

- `d_smile < -0.002`
- `d_asym < 0.008`
- `d_lip_raise >= -0.015`
- `d_mar < 0.03`
- `d_brow < -0.012`
- `-0.03 <= d_ear <= 0.04`

### `Sad`

Міміка: куточки рота опущені, очі не сильно заплющені, брови не зведені, асиметрія рота мала, верхня губа не опущена нижче допустимого рівня.

Абсолютний режим:

- `smile_coeff < -0.012`
- `ear_avg >= 0.245`
- `brow_dist >= 0.128`
- `mouth_asymmetry < 0.009`
- `upper_lip_raise >= 0.050`

Калібрований режим:

- `d_smile < -0.003`
- `d_ear >= -0.03`
- `d_brow >= -0.004`
- `d_asym < 0.008`
- `d_lip_raise >= -0.015`

### `Neutral`

Міміка: нейтральний або недостатньо виражений вираз обличчя.

Емоція `Neutral` повертається тоді, коли жоден із наборів правил для `Surprised`, `Fear`, `Happy`, `Contempt`, `Disgusted`, `Angry` або `Sad` не спрацював.

Залежності проєкту:

## Налаштування PostgreSQL

Перед запуском потрібно створити базу даних PostgreSQL і таблицю користувачів.

Приклад створення таблиці:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    face_coordinates TEXT,
    created_at TEXT NOT NULL
);
```

Підключення налаштовується через файл `.env` у корені проєкту.

Створи файл `.env` за прикладом [.env.example](.env.example):

```env
DATABASE_URL=postgresql://postgres:your_password@localhost:5432/emotion_recognition
```

Якщо база, користувач або пароль називаються інакше, зміни відповідні частини URL.

Формат:

```text
postgresql://USER:PASSWORD@HOST:PORT/DATABASE
```

Якщо змінна `DATABASE_URL` не задана, код спробує використати локальне підключення:

```text
postgresql:///emotion_recognition
```

## Запуск

```bash
python3 main.py
```

Після запуску відкривається повноекранний інтерфейс. У верхній панелі є кнопка `Exit`, яка повністю закриває застосунок.

Також можна використовувати:

- `F11` - перемикання повноекранного режиму;
- `Ctrl+Q` - закриття застосунку;
- `q` або `Esc` у вікні камери - завершення поточного розпізнавання.

## Основні сценарії

### 1. Режим `Try`

Цей режим призначений для швидкого запуску системи без акаунта.

Порядок роботи:

1. Користувач натискає `Try` на головному екрані.
2. Система відкриває вікно камери.
3. Виконується калібрування нейтрального виразу обличчя.
4. Запускається розпізнавання емоцій.
5. Дані користувача не зберігаються.
6. Координати обличчя не записуються в базу.
7. Після закриття вікна камери користувач повертається на головний екран.

У цьому режимі CSV/JSON-файли з результатами не створюються.

### 2. Авторизований режим

Цей режим потрібен для роботи зі збереженим профілем обличчя.

Порядок роботи:

1. Користувач натискає `Sign In`.
2. Можна увійти в наявний акаунт або створити новий.
3. Під час реєстрації створюється запис користувача в PostgreSQL.
4. Після входу відкривається екран акаунта.
5. Під час першого запуску розпізнавання система перевіряє поле `face_coordinates`.
6. Якщо координати ще не збережені, система відкриває камеру, зчитує обличчя та зберігає результат у базу.
7. Якщо координати вже є, система використовує збережений профіль і не виконує повторне зчитування.
8. Після запуску відкривається вікно розпізнавання емоцій.

Авторизовані сесії зберігають результати в папку `output/` у форматах CSV і JSON.

### Повторне зчитування обличчя

На екрані акаунта є кнопка `Recapture Face`.

Вона потрібна, якщо користувач хоче оновити збережений профіль обличчя.

Порядок роботи:

1. Користувач натискає `Recapture Face`.
2. Система відкриває камеру.
3. Виконується повторне зчитування обличчя.
4. Нові координати та baseline перезаписуються в поле `face_coordinates`.
5. Користувач повертається на екран акаунта.

## База даних PostgreSQL

Дані користувачів зберігаються в таблиці `users` бази PostgreSQL.

Таблиця створюється автоматично функцією `init_db()`, якщо її ще немає, але її також можна створити вручну SQL-командою з розділу налаштування.

Таблиця `users`:

| Поле | Опис |
|---|---|
| `id` | Унікальний ідентифікатор користувача |
| `username` | Логін користувача, має бути унікальним |
| `password_hash` | Хеш пароля, відкритий пароль не зберігається |
| `face_coordinates` | JSON зі збереженим профілем обличчя |
| `created_at` | Дата й час реєстрації |

Паролі зберігаються не у відкритому вигляді, а як PBKDF2-SHA256-хеш із сіллю.

Поле `face_coordinates` зберігає JSON-структуру з:

- `baseline` - індивідуальні базові значення параметрів обличчя;
- `landmarks_3d` - координати точок обличчя;
- `captured_at` - дата й час зчитування.

## Міграція зі старої SQLite-бази

Якщо в проєкті уже є старий файл:

```text
users.sqlite3
```

користувачів можна перенести в PostgreSQL скриптом:

```bash
python3 migrate_sqlite_to_postgres.py
```

Скрипт переносить:

- `username`;
- `password_hash`;
- `face_coordinates`;
- `created_at`.

Паролі повторно вводити не потрібно, тому що переносяться вже готові хеші.

Якщо користувач із таким `username` уже є в PostgreSQL, він не дублюється.

## Як працює розпізнавання

1. OpenCV відкриває потік вебкамери.
2. MediaPipe Face Landmarker знаходить точки обличчя.
3. З точок обчислюються геометричні параметри:
   - відкритість очей;
   - відкритість рота;
   - ширина рота;
   - коефіцієнт усмішки;
   - відстань брів;
   - асиметрія рота;
   - підняття верхньої губи.
4. Значення згладжуються через EMA-фільтр.
5. Класифікатор порівнює параметри з правилами.
6. В OpenCV-вікні відображаються точки обличчя, поточна емоція та параметри.

## Калібрування

Під час калібрування користувач має утримувати нейтральний вираз обличчя приблизно 3 секунди. Система збирає набір кадрів і обчислює індивідуальну базову лінію.

Якщо калібрування успішне, розпізнавання працює в режимі:

```text
CALIBRATED
```

Якщо обличчя не знайдено або калібрування скасовано, система може продовжити роботу в режимі:

```text
ABSOLUTE
```

## Помилки та повідомлення

В інтерфейсі передбачені повідомлення для основних ситуацій:

- не заповнено логін або пароль;
- користувач уже існує;
- неправильний логін або пароль;
- камера недоступна;
- обличчя не знайдено;
- користувача не знайдено.
